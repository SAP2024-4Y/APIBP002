1. Overview

ShopMesh is a dual-interface API — the same domain services power both a REST surface (OpenAPI 3.0.3, served at /docs) and a GraphQL surface (served at /graphql, Apollo Sandbox). Both interfaces are served from the same Node.js/Express process on port 8080.

SurfaceBase URLDocumentation
RESThttp://localhost:8080/api/v1/docs (Swagger UI)
GraphQLhttp://localhost:8080/graphql/graphql (Apollo Sandbox)
Healthhttp://localhost:8080/health—
Readinesshttp://localhost:8080/ready—

Roles

RoleActorDemo credentialsAuthentication
publicAny shopper or integration—None required
customerSigned-in shopperdemo / demo-passwordAuthorization: Bearer <token>
adminCatalogue manageradmin / admin-passwordAuthorization: Bearer <token>

Missing/invalid token → 401 UNAUTHENTICATED. Valid token without the required role → 403 FORBIDDEN.

2. Quick Start

Start the server

npm install
npm start
# → ShopMesh listening on http://0.0.0.0:8080

End-to-end booking in 4 curl commands

# Step 1 — Get a customer token
TOKEN=$(curl -s -X POST http://localhost:8080/api/v1/auth/token \
  -H 'Content-Type: application/json' \
  -d '{"username":"demo","password":"demo-password"}' | jq -r .token)

# Step 2 — Browse products
curl http://localhost:8080/api/v1/products?limit=5

# Step 3 — List slots for a product
curl http://localhost:8080/api/v1/products/prod_001/slots

# Step 4 — Book a slot (canonical REST path)
curl -X POST http://localhost:8080/api/v1/products/prod_001/slots/slot_001_2/bookings \
  -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"quantity":1}'

3. Authentication

POST /api/v1/auth/token public

Exchange demo credentials for a JWT (expires in 2 h).

curl -X POST http://localhost:8080/api/v1/auth/token \
  -H 'Content-Type: application/json' \
  -d '{"username":"demo","password":"demo-password"}'

# Response
{
  "token": "eyJ...",
  "token_type": "Bearer",
  "expires_in": "2h",
  "role": "customer"
}
POST /api/v1/auth/register public

Create a new customer account and immediately receive a JWT.

curl -X POST http://localhost:8080/api/v1/auth/register \
  -H 'Content-Type: application/json' \
  -d '{"username":"alice","password":"secret123","email":"alice@example.com"}'

4. Booking Flow — Stateless REST

Every REST request is self-contained. No server-side session is maintained between steps — the client carries all state in the URL and request body.

# 1. Discover products GET /api/v1/products?category=Electronics&status=active # 2. Select a product GET /api/v1/products/{id} # 3. See its available delivery slots GET /api/v1/products/{id}/slots?starts_at=2026-12-01T00:00:00Z # 4. Book a slot — full hierarchy in the URL (canonical) POST /api/v1/products/{id}/slots/{slotId}/bookings # 5. Confirm the booking GET /api/v1/bookings/{bookingId} # 6. Cancel if needed (releases slot capacity) DELETE /api/v1/bookings/{bookingId}
Why this design is stateless: The booking URL POST /products/{id}/slots/{slotId}/bookings encodes the complete resource hierarchy. The server needs no prior context — it validates the product exists, the slot belongs to that product, and the slot has capacity, all from the URL alone.

Booking conflict responses

409 codeWhendetails
SLOT_FULL Slot capacity is exhausted for the requested quantity alternatives[] — up to 3 open slots for the same product
BOOKING_OVERLAP Caller already holds a booking whose time window overlaps this slot conflicting_booking_id, conflicting_slot_id

5. REST — Products

GET /api/v1/products public

List products with filtering, sorting, and keyset cursor pagination.

ParamTypeDescription
statusstring enumactive | out_of_stock | discontinued
categorystring enumClosed enum, case-insensitive (see Category enum)
qstringSubstring match on name or description
min_price / max_pricenumber (INR)Price range filter, inclusive
sortenumcreated_at(default) | price | name | rating | id
orderenumdesc(default) | asc
limitintegerPage size, default 20, max 100
afterstringOpaque cursor from previous next_cursor
curl 'http://localhost:8080/api/v1/products?category=Electronics&status=active&limit=10'
GET /api/v1/products/map public

Geospatial search. Provide either a radius (latitude, longitude, radius_km) or a bounding box (min_lat, min_lon, max_lat, max_lon). Returns all matches in one response.

# Radius search — 50 km around Bengaluru
curl 'http://localhost:8080/api/v1/products/map?latitude=12.9716&longitude=77.5946&radius_km=50'

# Bounding box — Karnataka
curl 'http://localhost:8080/api/v1/products/map?min_lat=11.5&min_lon=74.0&max_lat=18.5&max_lon=78.5'
GET /api/v1/products/{id} public

Fetch a single product by id.

curl http://localhost:8080/api/v1/products/prod_001
POST /api/v1/products admin

Create a product. Requires all required fields in the body.

curl -X POST http://localhost:8080/api/v1/products \
  -H "Authorization: Bearer $ADMIN_TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{
    "name":"Monsoon Trek Backpack","category":"Sports","status":"active",
    "price":2499,"inventory":40,"latitude":18.5204,"longitude":73.8567
  }'
PATCH /api/v1/products/{id} admin

Partially update a product. Send only the fields to change.

curl -X PATCH http://localhost:8080/api/v1/products/prod_001 \
  -H "Authorization: Bearer $ADMIN_TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"status":"out_of_stock","inventory":0}'
DELETE /api/v1/products/{id} admin

Delete a product and cascade-delete its slots and bookings in one transaction.

6. REST — Slots

Slot fields

FieldTypeDescription
idstringUnique slot id
product_idstringProduct this slot belongs to
starts_atISO 8601 UTCDelivery window start
ends_atISO 8601 UTCDelivery window end
capacityintegerMaximum bookings
bookedintegerConfirmed bookings
availableintegercapacity − booked
GET /api/v1/products/{id}/slots public

List delivery slots for a specific product, with optional time-window filter. Use this before booking to show the customer which slots are available.

# All future slots for a product
curl 'http://localhost:8080/api/v1/products/prod_001/slots?starts_at=2026-12-01T00:00:00Z'
GET /api/v1/products/{id}/slots/{slotId} public

Fetch a single slot scoped to a product. Returns 404 if the slot does not belong to this product.

curl http://localhost:8080/api/v1/products/prod_001/slots/slot_001_1
POST /api/v1/products/{id}/slots admin

Create a new delivery slot for a product. ends_at must be strictly after starts_at.

curl -X POST http://localhost:8080/api/v1/products/prod_001/slots \
  -H "Authorization: Bearer $ADMIN_TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"starts_at":"2026-12-15T09:00:00Z","ends_at":"2026-12-15T12:00:00Z","capacity":20}'
GET /api/v1/slots public

Cross-product time-window slot search. Use when you need slots across multiple products (e.g. a calendar view). Optionally narrow with product_id.

# All slots in December
curl 'http://localhost:8080/api/v1/slots?starts_at=2026-12-01T00:00:00Z&ends_at=2026-12-31T23:59:59Z'
GET /api/v1/slots/{id} public

Fetch a single slot by id (not scoped to a product).

curl http://localhost:8080/api/v1/slots/slot_001_1

7. REST — Bookings

Booking fields

FieldTypeDescription
idstringUnique booking id
slot_idstringThe booked slot
product_idstringProduct the slot belongs to
userstringUsername who made the booking
quantityintegerUnits booked (≥ 1)
created_atISO 8601 UTCWhen the booking was created
POST /api/v1/products/{id}/slots/{slotId}/bookings customer admin

Canonical booking creation. The full product → slot → booking hierarchy in the URL makes this endpoint self-contained and stateless. quantity defaults to 1.

curl -X POST http://localhost:8080/api/v1/products/prod_001/slots/slot_001_2/bookings \
  -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"quantity":1}'

# Response 201
{
  "created": {
    "id": "bk_a3f9c1...",
    "slot_id": "slot_001_2",
    "product_id": "prod_001",
    "user": "demo",
    "quantity": 1,
    "created_at": "2026-11-28T10:00:00.000Z"
  }
}
GET /api/v1/bookings customer admin

List all bookings owned by the authenticated caller.

curl http://localhost:8080/api/v1/bookings \
  -H "Authorization: Bearer $TOKEN"
GET /api/v1/bookings/{id} customer admin

Fetch a single booking (own only). Returns 403 for bookings belonging to another user.

curl http://localhost:8080/api/v1/bookings/bk_a3f9c1 \
  -H "Authorization: Bearer $TOKEN"
DELETE /api/v1/bookings/{id} customer admin

Cancel an owned booking. Releases the slot capacity immediately (atomic). Returns 403 for other users' bookings.

curl -X DELETE http://localhost:8080/api/v1/bookings/bk_a3f9c1 \
  -H "Authorization: Bearer $TOKEN"

# Response 200
{ "id": "bk_a3f9c1", "slot_id": "slot_001_2", "cancelled": true }
POST /api/v1/bookings deprecated customer

Flat booking creation. Accepts {"slot_id":"...","quantity":1}. Response includes Deprecation: true header. Use the product-scoped path instead.

The GraphQL schema mirrors the REST domain. Use http://localhost:8080/graphql in Apollo Sandbox to explore interactively. Authentication uses the same Authorization: Bearer <token> header (set it in the Headers panel).

11. Standards & Conventions

Money

All prices are stored and returned as integer paise (price_paise). The convenience price field (rupees as a float) is deprecated — use price_paise / 100 for display and price_paise for all calculations to avoid floating-point rounding.

// Correct
const displayPrice = (product.price_paise / 100).toFixed(2);  // "24.99"

// Avoid
const displayPrice = product.price;  // deprecated float, may lose precision

Timestamps

All timestamps are ISO 8601 UTC with a Z suffix, e.g. 2026-12-01T09:00:00.000Z.

Coordinates

GeoJSON (RFC 7946) order: [longitude, latitude] (note: longitude first). WGS 84 degrees.

Pagination

Keyset cursors — no page numbers. Pass next_cursor as after for the next page. Cursors are opaque; do not parse or modify them. has_more: false means you are on the last page.

// First page
GET /api/v1/products?limit=20
// → { data: [...], has_more: true, next_cursor: "eyJ...", total_count: 555 }

// Next page
GET /api/v1/products?limit=20&after=eyJ...

Rate Limits

120 requests per 60-second window per IP. Response headers: RateLimit-Limit, RateLimit-Remaining, RateLimit-Reset. On 429, a Retry-After header gives the wait in seconds.

Category enum

Electronics · Fashion · Home & Kitchen · Books · Grocery · Sports · Beauty · Toys & Games · Health & Wellness. Input matching is case-insensitive; the response always returns the canonical spelling.
